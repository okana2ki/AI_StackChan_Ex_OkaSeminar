## ✅ 音が「速い・ギザギザ途切れる」問題（2026-08-14 解決）

症状: AI の声が**早口になり、絶えず途切れる**。ネット回線やモデルを疑いがちだが、**再生側のバグ**だった。

原因は2つ。**両方直さないと解決しない**。

### 主犯：`playRaw()` のチャンネル指定漏れ

```cpp
bool playRaw(const int16_t*, size_t, uint32_t sample_rate = 44100,
             bool stereo = false, uint32_t repeat = 1,
             int channel = -1,            // ← 既定は「自動割り当て」
             bool stop_current_sound = false);
```

`channel` を省略すると **-1（空いている仮想チャンネルへ自動割り当て）**になる。
音声チャンクが毎回ちがうチャンネルに載り、**複数チャンクが同時に鳴っていた**。

- 重なって鳴る → **速く聞こえる**
- 重なり方が毎回変わる → **ギザギザ・途切れて聞こえる**
- さらに順番待ちのコードは `isPlaying(0)`（ch0）を見ていたのに、データは別チャンネルへ
  行っていたため **待ちが一切機能していなかった**

修正（`RealtimeLLMBase.cpp` `streamAudioDelta()`）:
```cpp
while (M5.Speaker.isPlaying(0) > 1) { vTaskDelay(1); }
M5.Speaker.playRaw((int16_t*)buf, len/2, 24000, false, 1, 0);  // ← ch0 に固定
```

### 共犯：バッファが2枚だった

`playRaw()` は**バッファをコピーせずポインタのまま再生する**（M5Unified のヘッダに
「実行時生成データは3枚を順番に使うこと」と明記あり）。2枚だと

- 「鳴り終わるまで待つ」しかない → チャンク間に無音の隙間ができて途切れる
- 無理にキューへ積むと再生中の面を上書きして音が飛ぶ

`AUDIO_BUF_NUM = 3` にし、`nextBufIdx` を 0→1→2→0 で回す。
`isPlaying(0) > 1` の間だけ待つ＝常に1つ先を仕込む状態を保てる。使用中は最大2枚なので
3枚あれば書き込み先が必ず空いている。

> **バッファ3枚だけ先に直しても症状は変わらない。** チャンネルが -1 のままだと
> そもそも列に並ばないため。順序として ch 固定が本丸。

## ⚠️ 無料枠切れの症状（2026-07-27 に丸一日溶かした罠）

Gemini Live の無料枠を使い切ると、**「枠切れ」と分かるエラーが返ってこない**。
症状だけ見ると設定バグに見えるため、コードを疑って延々と直そうとしてしまう。

### 枠切れのときに実際に出る症状

| 観測されたもの | 実際の意味 |
|---|---|
| 1ターン目だけ成功し、2ターン目以降が無応答 | 残っていた枠を使い切った |
| `[WSc] modelTurn without audio` が連発 | 音声生成が止まりテキストにフォールバック |
| `[WSc][CLOSE] code=1007 The audio content type (CONTENT_TYPE_AUDIO) is not supported for this model configuration` | **枠切れ。設定は正しい** |
| `[WSc][CLOSE] code=1011 Internal error occurred.` | **同上** |
| `[WSc][CLOSE] code=1011 You exceeded your current quota...` | ようやく明示された（別モデルに変えたら出た） |

**1007 の文言は完全に誤解を招く。** 「モデル設定が音声入力に非対応」と書いてあるが、実際は枠切れ。

### 枠切れかどうかの確定方法

1. **AI Studio の使用状況ページを見る**（これが最速・確実）
   https://aistudio.google.com/app/usage
   - `API エラーの合計数` に **429 TooManyRequests / 500 InternalServerError** が出ていれば枠切れ
   - `モデルごとの出力トークン数` の凡例に該当モデルが**出てこない**＝出力できていない
2. **別モデルに切り替えてみる**（`gemini-3.1-flash-live-preview` 等）。
   枠切れなら `You exceeded your current quota` と明示されることがある
3. **無操作で接続だけ維持する**と切断しない＝設定は正しい。音声送信時だけ落ちるなら枠切れを疑う

### この罠で無駄にした対処（すべて主犯ではなかった）

VAD設定 / 関数呼び出し / プロンプト長 / mime形式 / googleSearch の有無。
**症状から推測してコードを直す前に、必ず使用状況ページを見ること。**

> なお `mime_type` へのレート付与（`audio/pcm;rate=16000`）と parts 全走査は、
> 枠切れとは別に実際の不具合だったので修正済み。

## 操作方法（実機・2026-07-27 の日本語UI改修後）

- **画面のどこでもタップ** → **録音開始**（当たり判定は右端40pxを除く全画面。指を離した瞬間に判定）
  - **タップで停止はしない。** 停止は Gemini の発話終了検知か 8 秒のタイムアウトに任せる。
    以前はトグルだったため、反応が分からず連打した来場者が偶数回叩くと録音が切れ、
    「触ったのに返事が来ない」状態になっていた（実機ログで確認）
  - 800ms のデバウンスあり。録音中の再タップは停止ではなく「聞く時間の延長」
- **AI 発話中のタップは無視される**（音声ミューテックス起因の本体フリーズを防ぐため）
- **右上を2秒長押し** → mod切替（スタッフ用の隠し操作。発話中・録音中は切り替わらない）
- **左右フリックでの mod 切替は廃止**（来場者が英語のデバッグ画面に迷い込む事故を防ぐため）
- 録音は **8 秒**でタイムアウト（`REALTIME_RECORD_TIMEOUT`。30秒→12秒→8秒と短縮）

## 診断ログ（展示当日まで残す方針）

「推測せず切り分ける」ための出力。シリアル 115200 で見る。
実際、これを入れる前に原因を2回誤診している（記憶ツール説・ハートビート説）ので、

| プレフィックス | 内容 | 使いどころ |
|---|---|---|
| `[ALIVE] loop running (N laps) touchCount=` | 5秒ごと。メインループの生存とタッチ検出数 | **画面は動くのに反応しない**とき。出力が止まればループがフリーズ（正常時は約9万周/5秒） |

| `[WSc][CLOSE] code=... reason=...` | サーバ都合の切断理由 | モデル名不正・権限エラーの特定（これで 1008 を突き止めた） |

## 2026-07-27 の改修（日本語UI化＋展示向け堅牢化）

多角調査で**検証済みの重大バグが複数**見つかったため、UI日本語化と併せて修正した。

### 直したフリーズ系バグ（すべて実コードで裏取り済み）

| # | 症状 | 原因 |
|---|---|---|
| 1 | AI発話中にタップすると**本体が固まる** | `sw_tone()` が `enterMutexAudio()` で無限待ち。発話中は `webSocketLoopTask` が turnComplete までミューテックスを保持し続けるため、loopタスクが発話終了まで停止していた |
| 2 | スワイプで**録音開始とmod切替が二重発火** | `wasPressed()`(触れた瞬間) で録音、`wasFlicked()`(離した瞬間) でmod切替。しかもフリック判定が既定 8px しかなく、指のブレで簡単に誤爆 |
| 3 | 発話中にフリックすると**電源を抜くまで復帰不能** | ミューテックスを保持したまま `vTaskSuspend` され、以後 `enterMutexAudio()` するもの全部が永久ブロック |
| 4 | `Mic.record()` 失敗時に**古い音声を送り続ける**＋1秒固まる | 失敗しても打ち切らず、`delay(1000)` がミューテックス保持中にあった |

**対策**: `display_touched()` の先頭で発話中は return（※これが無いまま `sw_tone()` を非ブロッキング化すると、
発話中に録音が始まり **WSタスクが自分の持つ非再帰ミューテックスを再取得して永久停止**する。順序が重要）／
`tryEnterMutexAudio(200)` を追加して UI 側は時限待ちに／タッチ判定を `wasReleased()`＋移動量40px未満に／
フリックによる mod 切替を廃止し右上長押しへ（`isBusy()` でガード）。

### その他の改善

- **日本語フォントの設定を `avatar.init()` より前に移動**。後だと描画タスク起動後に設定されるため、
  起動直後の数フレームが `speechFont == nullptr` で ASCII フォントにフォールバックし日本語が豆腐になる
- **接続状態を画面に出す**。以前は WiFi 断でも API キー失効でも `Please touch` のままで故障に気づけなかった
- **未接続時はタップで録音を始めない**。`sendTXT()` は未接続だと黙って捨てるので、来場者が
  「死んだ回線」に向かって12秒話し続ける事故が起きていた
- **`enableHeartbeat(15000, 3000, 2)` を追加**。未設定だと ping を打たず、TCP が半開きになると
  `isConnected()` が true のまま張り付いて自動再接続が一生走らない（最も気づきにくい壊れ方）
- **表情と首振りを復活**。`idle()` の中身が丸ごと `#ifdef REALTIME_API_WITH_TTS` の中にあり、
  このフラグは `platformio.ini` でコメントアウトされているため**デッドコードだった**。
  待機/録音中/応答中で表情と `servo_home` を切り替える。ただし LLM も `set_avatar_expression` で
  表情を変えるため、**状態が遷移した瞬間だけ** `setExpression()` する（毎ループ呼ぶと会話中の表情を潰す）
- **連打デバウンス**（800ms）と**最短録音時間**（1.5秒）。反応が無いと来場者は必ず連打し、
  偶数回叩くと「触ったのに何も起きない」状態になっていた
- 起動画面・SDエラー・WiFiエラーの日本語化

### 既知の未対応（調査済み・今回は見送り）

- **CoreS3ではサブウィンドウが描画されない**。`Face.cpp` が `scale != 1.0 || rotation != 0` の
  ときしか `subWindow->draw()` を呼ばず、CoreS3 は scale=1.0 のため **QR表示・アラーム表示が全部不可視**。
  直すなら `lib/m5stack-avatar/src/Face.cpp` の else 側に描画を追加（lib配下なのでビルドで消えない）
- **キャラクターyamlが realtime ビルドで読まれていない**。`loadCharacter()` の呼び出しが
  `Robot.cpp` の `#else //REALTIME_API` ブロック内にあるため、`butler.yaml` 等が一切効かない。
  実際に使われているのは `LLMBase.cpp` の `defaultRole`（英語1文）。
  **オープンキャンパス用の人格（応答を2文以内に制限）を入れるならここの有効化が必要**
- Gemini 側の自動VADが常時ON。騒がしい会場では環境音を発話と誤検知して勝手に喋り続ける可能性。
  `realtimeInputConfig` で感度を下げるか、手動 `activityStart/End` に変えるのが本命
- ウォッチドッグ (`init_watchdog()`) がコメントアウトのまま
